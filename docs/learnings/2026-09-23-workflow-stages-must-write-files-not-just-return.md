# A long Workflow must persist each stage to disk, or a mid-run failure loses everything

**Problem** — A 128-agent Workflow ran for 7 hours and returned `{"inventory":[],"competitors":[],"strategy":[]}`. 97 of 128 agents had failed with "You're out of usage credits" partway through, and the pipeline's return value was empty because the later stages never ran.

**Approach** — The empty result looked like total loss, but the tool's own diagnostics point at `journal.jsonl` before diagnosing. The cheaper check first: the stage-1 prompts had each instructed their agent to *write its JSON to a scratch file* as well as return it. `ls` on the scratch directory showed 31 completed files — 11 of 11 inventory readers and 20 of 21 competitor researchers had finished and persisted before the credits ran out. Only the verify, reconcile and strategy stages were lost. Recovery was then a second, smaller Workflow that read the existing files, filled the one missing competitor, verified the highest-stakes subset, and ran the final synthesis — not a re-run of the 7 hours.

**Solution** — No repo change. Phase 2 (23 agents, 0 errors) consumed `scratchpad/review/*.json` from phase 1 and completed the work. Both phase scripts are kept under the session's `workflows/scripts/`.

**Rule** — In any Workflow whose stages cost real time or money, instruct every agent to write its structured result to a file under the scratchpad directory *in addition to* returning it, and give the file a deterministic name (`<stage>-<key>.json`). Then a killed, throttled or credit-exhausted run is resumable by inspecting the directory rather than replayable only from cache. Design the recovery as a second workflow that reads those files, not as a resume of the first — `resumeFromRunId` only replays agents whose `(prompt, opts)` are byte-identical, which a changed script breaks. Also: put the expensive barrier late. A `parallel()` barrier that gates synthesis behind *all* verifiers means one slow agent blocks the whole final stage.

**Dead ends** — Assuming an empty return value means empty results (the per-agent files and `journal.jsonl` both survived). Reaching for `resumeFromRunId` first: it is the right tool only when the script is unchanged, and here the recovery deliberately changed the plan. Polling the scratch directory in a tight loop — foreground `sleep` is blocked; use `run_in_background` with an `until` loop and let the completion notification arrive.
